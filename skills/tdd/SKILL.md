# 测试与 TDD

默认快速开发。新增、重构或删除文件、class、函数本身都不是新增测试的理由。测试保护当前需要的行为，不记录代码改动历史。

## 新增测试的门槛

先看受影响的现有测试。只有能说明「当前需求是什么、哪种现实错误会违反它、现有验证为什么不足」时才新增用例；说不清就直接实现并做已有检查。这个判断不要求额外文档或固定格式汇报。

期望值必须来自需求、协议或独立事实，不从刚写的实现反推。错误实现应让断言失败；换一种内部实现但契约不变时应仍通过。可以用一个具体错误检查断言价值，不必为此引入 mutation testing 工具或固定流程。

## 选择验证方式

- 业务规则、金额／日期换算、字段映射、权限、幂等、状态机和错误分支：能从需求独立写出输入与预期，就用少量契约测试。错误实现必须能让断言失败。
- 修 bug：先用现有测试或浏览器复现错误，再修复并验证。需要持久回归保护时增加对应行为用例。
- 删除功能、废弃分支、兼容层或死代码：直接删除并按下一节清理；纯重构优先运行受影响的已有行为测试与工程检查。
- 文案、样式、布局：使用浏览器验收；同步必要的已有断言或 locator，不为红转绿新增结构测试。
- 接线、类型、薄包装和脚手架：优先类型检查和受影响的已有测试；包含可算错的参数映射或失败路径时按行为契约处理。
- 探索或原型：先跑通，契约稳定后再固定预期。

## 删除就删干净

- 同步删除只服务于被移除功能的测试、fixture、mock 和快照；混合用例只去掉失效部分，保留仍有效的行为断言。
- 不新增「防恢复 / block recovery」测试来断言旧文件不存在、源码不含旧符号、旧函数不再导出、旧实现没有被调用。用一次性的引用搜索、diff 审查和类型检查确认清理情况；不要把这些检查固化为测试、扫描脚本或 CI 禁词规则。
- 不把旧测试改成「已移除版本」，不留下空壳、`skip` / `todo` 或纪念性注释，也不为让旧测试通过保留占位实现、兼容开关或额外拒绝分支。
- 只有当前需求独立要求一个可观察结果，且现有验证不足时，才补该行为用例。例如明确要求旧协议返回指定错误，或敏感字段不得进入响应，应通过真实入口验证结果；不能仅凭「删除」推导出新的拒绝、兼容或防恢复契约。

不要把负向断言一概删掉：越权写入被拒绝且数据未变、取消后不再发送请求等仍可能是有效需求。安装器／清理器运行后应删除指定文件并保留用户文件，也是运行时契约，区别于断言仓库里某个旧文件不存在。

## 避免无用测试

- **结构锁定**：文件存在、组件仅能 mount、符号导出、私有方法名、内部状态和非契约性的调用顺序。优先类型检查、导入解析、lint 和已有消费者测试；用公共入口的结果验证实际接线。
- **自证预期**：复制生产算法算 expected、从被测配置生成 expected、把刚跑出的结果直接当快照答案。简单业务事实可以硬编码；关键是预期能独立判对错。
- **只测 mock 或依赖**：mock 掉被测逻辑再断言 mock 返回值、手动调用回调再断言它被调用、重复测试标准库／第三方库。保留真实被测路径，只在必要边界替换外部依赖；请求参数、幂等调用次数等确属契约时可以验证交互。
- **宽松或空洞断言**：只判 truthy／有定义而不验证关键结果；在空集合循环、条件分支或吞错代码里放断言导致零断言通过；遗漏异步等待。断言必须实际执行，错误必须传到测试运行器。
- **快照和覆盖率堆量**：整页快照锁住无关文案／DOM、机械枚举同一等价类、为每层薄包装重复同一断言。围绕独立规则与风险选代表输入和边界；不同层只有覆盖不同失败原因时才值得各测。
- **为测试造实现**：为了易测而新增业务不需要的导出、抽象、注入开关、fallback 或防御分支；再测试这些新增结构。先缩小被测边界，复用项目已有测试接缝，不用测试为额外代码找理由。

遇到删除、mock、快照或覆盖率驱动的测试清理，按需查看 [常见误区与来源](references/test-value.md)。

## 有效用例的组织

测试命名应说清行为，便于定位失败。不要机械地按是否出现 `and`、用了哪种断言 API 或有几个组合判定质量。优先覆盖可组合的叶子规则；风险确实来自交互时保留有意义的组合用例。

```ts
expect(mapRole('viewer')).toEqual({ canEdit: false, canView: true })
expect(createOrder({ amount: -1 }).code).toBe('INVALID_AMOUNT')
```

## 完成条件

沿用仓库现有验证方式，不为小改动新建测试栈。先运行受影响的检查；仅在新失败或未覆盖风险需要时扩大范围。前端变更完成浏览器验收。测试先后顺序服务于独立契约与错误复现，不把流程仪式当作验证结果。

已有测试失败时，先判断契约是否仍成立：随需求废弃的断言应删除或更新；仍有效的断言不能为变绿而放宽、跳过或直接照抄实际输出。清理限于当前改动及直接相关用例，不借机重写整套测试。没有新增测试也可以完整交付；报告实际验证结果即可。
