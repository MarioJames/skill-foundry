# 记忆协议

`MEMORY.md` 不是工作日志、提交摘要或第二份知识图谱。它只保存其他持久化工具无法可靠恢复、但会改变后续 agent 行为的工作上下文。协议和消费门禁写入生成的 `AGENTS.md`；`MEMORY.md` 不复制规则，无条目时只保留标题与空占位。

## 写入门槛

写入前依次判断：

1. 代码、git commit / PR、CI、任务系统、当前外部状态或 `.workspace/` 事实源能否可靠恢复？能恢复就不写。
2. 遗漏后是否会导致重复询问、误解用户、进入错误范围、重复外部操作或丢失接续点？不会就不写。
3. 是否来自可归因的用户输入、用户确认或明确观察，而非 agent 猜测？推断只能标成推断，不能伪装成用户偏好或确认。
4. 是否属于工作上下文且不含凭证、敏感个人信息、临时 ID 或无关画像？不满足就不写。

同时通过四项才写。稳定项目事实仍应晋升到图谱事实源；记忆只保留无法被该事实源表达的来源、纠正或接续语境。

## 条目类型

- `[偏好]`：用户明确表达、会在同一作用域后续复用的工作方式或输出偏好；已存在于用户级指令或 `AGENTS.md` 的规则不重复。
- `[纠正]`：用户纠正了旧名称、范围、归属、假设或目标。记录正确结论和被否定的误解，不能只写“已确认”。
- `[用户操作]`：用户在仓库之外完成的授权、部署、数据变更、发布、审批或环境操作。记录目标环境/对象和来源；再次依赖前仍验证当前状态。
- `[确认决策]`：用户明确确认、但无法从最终代码反推出理由的取舍。agent 自行判断不使用此标签。
- `[接续]`：未决问题、阻断原因、下一步和恢复条件。问题解决后删除，或在仍有历史价值时标明已被哪条结论替代。

## Scope 分层

`MEMORY.md` 保持 Markdown，但用机器稳定的标题表达父子作用域：

- `## workspace`：跨仓工作方式、工作区级称呼/纠正和影响多个项目的外部状态。
- `## repo:<repo>`：只影响 `repo_order` 中某个仓库的偏好、纠正或用户操作，例如 `## repo:imctl-ai`。
- `### task:<task-key>`：嵌套在 `workspace` 或某个 `repo:<repo>` 下，表示工作区级跨仓任务或该项目内任务。`task-key` 使用稳定的英文/数字 slug；任务完成且没有剩余语境时删除该小节。

相同 scope 的记录放在同一分节，不重复创建同名标题。跨多个仓库的临时目标放在 `workspace > task`；单仓任务放在 `repo:<repo> > task`。稳定跨仓规则应晋升到图谱，只有无法被图谱表达的用户语境留在 workspace scope。

这里不改用 JSONL：它会为每条重复 scope/字段并增加转义噪声；也不使用 YAML，因为技能当前坚持零依赖解析，缩进错误会让整份记忆失效。scope 化 Markdown 仍能用 `rg '^## repo:...'` 精确定位，也便于人直接审阅。若未来出现大量自动查询/并发写入需求，再把结构化文件设为真源并生成 `MEMORY.md`，不要同时手工维护两份。

## 紧凑格式

```markdown
## repo:example-repo

### task:rename-entry

- `2026-07-10` `[纠正]` 来源：用户明确纠正；结论：后续统一使用 `new-name`，旧称不再作为入口。
```

每条记录保持单行，便于 diff、搜索和机械校验。日期表示获知或最后确认时间，不代表内容永远有效。同一 scope 下按日期由新到旧排列；新记录纠正旧记录时直接压缩或删除旧记录，不把 MEMORY 当不可变事件日志。

每条至少回答：

- 范围：由 `workspace` / `repo:<repo>` 父级和可选的 `task:<task-key>` 子级表达；环境/对象可写进结论。
- 来源：用户明确说明、用户确认、agent 观察或 agent 推断。
- 当前有效结论：未来 agent 应据此改变什么行为。

若信息容易失效，补充“截至日期”“待验证”或替代关系。当前用户指令纠正旧记忆时，直接更新、压缩或删除旧条目，不要留下两个看似同时有效的结论。

## 明确排除

- `bootstrap`、`scan`、`init`、`validate` 成功，扫描仓库数量和生成文件清单。
- 修改了哪些文件、实现了哪些函数、跑过哪些测试、精确产物数量、subagent / reviewer 流水账。
- 当前代码结构、仓库定位、关系、稳定命令、接口/字段/包清单；分别由源码、git、CI、`discovery.json` 或图谱事实源承载。
- 可从 commit / PR / issue 完整恢复的完成摘要；若某个不可反推的用户理由重要，只记录理由和适用范围。
- 密钥、token、账号、个人隐私、临时 ID、易变 URL/主机名或与工作无关的个人偏好。

## 晋升与压缩

- 稳定对象称呼和任务触发词：晋升到 `.workspace/metadata.yaml` 的 `task_routes`。
- 仓库入口、非显然操作和误操作护栏：晋升到仓库 `index.md`。
- 业务边界、流程和共享机制：晋升到 `domains/` / `shared/`。
- 跨仓机制、契约面和双侧证据：晋升到 `.workspace/metadata.yaml`，再运行 `init` + `validate`。

记忆是当前接续面，不是不可变审计日志。每次相关任务结束时删除已解决接续、已失效外部状态和已被权威来源完整承载的实现细节；合并同一主题的重复条目。需要追溯代码变更时使用 git/PR，不靠 MEMORY 保存副本。

## 按需消费

只有以下情况读取：

- 用户提到“上次”“继续”“之前”“还是按原来”等续接语义。
- 当前任务确实依赖用户偏好、纠正、确认取舍或用户完成的外部操作。
- 任务对象称呼无法由 `AGENTS.md` 路由和当前事实源消歧。
- 需要恢复未决事项、阻断或下一步。

先按 scope 定位，再用任务关键词、对象名、类型标签或日期缩小记录，不默认加载全文。消费时遵循：当前用户指令 > 当前代码/配置/外部实时状态 > 图谱事实源 > 历史记忆。记忆只提供线索，不证明当前代码或外部状态，也不授权重复执行过去的部署、发布、迁移或数据操作。

## 存量审计

刷新已有工作区时，对 `MEMORY.md` 做一次压缩评审：

1. 删除纯图谱初始化/刷新和可由 git、代码、CI、任务系统或 `.workspace/` 反查的条目。
2. 把仍有价值的稳定事实晋升到正确事实源。
3. 将用户偏好、纠正、用户操作、确认决策和接续状态归入 `workspace` / `repo:<repo>`，任务语境再嵌套 `task:<task-key>`，改成带日期、类型、来源和结论的单行记录。
4. 删除已解决或已失效内容；无法确认是否仍有效时标为待验证，不把旧记录当现状。
5. Review Agent 对照本轮用户输入检查“该记而未记”；脚本只能发现旧格式和明显流水账，不能推断缺失的用户语境。
