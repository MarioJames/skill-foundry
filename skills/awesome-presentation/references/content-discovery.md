# 内容整理与讨论

仅在用户要求共同打磨内容，或存在影响正确性的关键缺口时读取讨论流程。材料与目标足够、或用户授权“直接做 / 你定 / 别问了”时，内部整理页表后直接实现，不要求用户另批 Spec。

## 直接完成时的内部页表

先读提供的长文、旧 PPT、仓库讲稿，提炼主张和页序，避免逐段照搬原文。内部记录：

- 听众、时长/页数、场景、核心主张、成功标准；未明确且可合理决定的偏好标记为假设。
- 每页一行：`id / section / sectionEn / title / takeaway / intent 草案 / 证据或素材`。
- 裁剪：合并重复页、删冗余、改口播、待补素材。

页表用于约束实现，可在内部维护；用户要求文档时才另行交付或落盘。它不必成为阻止工程动作的批准产物。只要能在请求范围内完成，就继续初始化、落页和验收，见 [初始化](init-and-setup.md) 与 [实现](content-to-deck.md)。

## 讨论路线

按缺口选择问题，不机械走完决策树。已明确或已授权自行决定的内容不再问。一次聚焦一个关键决策，给推荐和简短理由；分段讨论只在用户希望逐段打磨时使用。

1. **目的与听众**：演示后听众要理解什么、做什么；已有材料能回答的先查。不能确定且会影响事实表达或结论时澄清。
2. **核心主张**：用一句立场串起材料，其余主张作支撑；只有主题词但授权你定时可自行拟定，不能补造未知事实。
3. **叙事弧**：方案汇报可用“问题→方案→证据→行动”，教学用“目标→步骤→示范→总结”，选型用“背景→对照→推荐→风险”。确有不同目标取舍时提供 2–3 条方案和推荐。
4. **证据素材**：区分可上屏事实、口播和需要可视化的材料。缺图/缺数时标待补或改文字，不编造生产统计。
5. **范围裁剪**：优先合并重复收益、把细节移到附录/口播，每页保留一个 takeaway；用户已授权内容取舍时自行完成。
6. **页表**：主张和证据足够后整理有序页表。用户要求先审大纲时交付并等待其决定；用户已要求完整制作时继续实现。

## 实现中的调整

页表与容量冲突时，在已授权的页数、目标与核心主张范围内拆页或换 recipe，并同步页表。只有影响真实性、改变固定约束或超出用户授权的取舍才提问；不得缩字号硬塞或用假数据补证据。已有批准的大纲保留其明确固定的内容，普通措辞和布局调整无需逐页重批。
