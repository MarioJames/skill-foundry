# 收尾：回收、保留与汇报

## 收尾回收

- **本任务的一次性资源默认回收，不等用户确认。** 包括临时目录、fixture、隔离的测试数据、容器和卷、worktree、自测用的 R2 对象。前提是归属明确、交付和交接已完成、对它的依赖已结束。
- **worktree 和分支合入后清理**，见 [分支](worktree-branch.md#分支)。
- **构建产物同样回收。** 一次性目录里的 `.next`、`dist`、`.vite` 在服务停止、复验结束后回收；项目正在使用的产物和工具共享的缓存不动。
- **失败现场**只在后续诊断确实需要、又不能简单重建时保留；能复现的先存最小诊断信息再回收。
- **跨会话的暂存目录**放在工作区外，在交接记录里写明所有者、依赖和释放条件，条件满足就回收。
- **worker 的资源由父 Agent 负责到底。** worker 自己回收，或在交接里逐项列出名称、路径或端口、依赖和释放条件。父 Agent 确认交付物和证据完好后回收，不写「留给 owner 审查后处置」。

## 什么要留

- **要留：** 最终报告和分享链接、必要的证据、开发数据库及迁移记录、用户要求保留的环境、别人正在使用的资源。
- **保留临时资源要写明**所有者、具体依赖和释放条件。条件是本任务结束前能核对的事件，在任务内满足的当场回收。「以后可能还要复验」「留给用户审查后处置」不是理由；确需跨任务保留的交用户决定。
- **不扩大清理范围。** 不用 `docker volume prune`、`docker system prune`、不属于本任务的 `docker compose down -v`、批量 `rm /tmp/*`。共享实例、数据卷、Redis、对象存储只按精确归属清理。

## 收尾自检与汇报

```bash
bun <skill-dir>/scripts/scan.ts --task <任务名> --workspace <工作区根> --clean
```

- 带 `--task` 只报三样：带任务名的资源、任务期间新出现却没有归属标记的东西、其余的个数。时间窗从任务临时根的创建时间算起。
- `--clean` 只删带任务名的：临时根，以及已合入、无改动、无进程占用的 worktree 和它的本地分支。别人的东西不动，不加 `--clean` 只列出。
- 容器、卷、分享对象、未跟踪文件和工作区根杂项脚本不删，按输出里的规则处理。
- 输出里出现「没有归属标记」的东西而它确实是本任务建的，说明创建时漏了任务名：回收它，下次创建时带上。
- 不带 `--task` 是整机盘点，用户要整理环境时才跑。这时 `--clean` 清的是不分归属的低风险项：已合入且闲置超过 24h 的 worktree、失效的 worktree 记录、已合入的本地分支（留恢复记录）。带标签且释放条件已满足、所属任务已结束的别人的资源，列为可回收交用户确认，不自己删。
- 最终回复分开写「已回收」和「仍保留」，保留项带原因、所有者和释放条件。

## R2 分享对象

```bash
bun <feature-delivery>/scripts/share.ts list [--task <任务>]
bun <feature-delivery>/scripts/share.ts remove --task <任务> [--key <对象或页面 key>]...
```

- **交给用户的链接永久保留**，包括设计文档、验收报告、它们引用的证据和所有历史版本。
- **自测、探测和核对失败的上传收尾时删除。** `remove` 只删登记在该任务名下的对象，被改写过的会拒绝并列出；不按前缀批量删除，不碰未登记的文件。
- 删除前被访问过的图片等可缓存文件，边缘缓存可能继续提供最多 4 小时。
- 上传方式、公开目录和登录配置见 feature-delivery 的 [分享链接](../../feature-delivery/SKILL.md#分享链接)。
