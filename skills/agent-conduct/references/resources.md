# 资源落点与创建

工作区根指仓库所在的上一级目录，例如 `~/workspaces/<项目组>/`。

| 产物 | 位置 | 生命周期 |
| --- | --- | --- |
| 源码改动 | 仓库工作树，或 `wt.ts add` 建的 worktree | 按项目流程提交 |
| 报告 | `<工作区根>/reports/`，按任务分文件或子目录，名称含主题和日期 | 持久 |
| 验收证据 | `<工作区根>/evidence/`，按任务分子目录 | 持久，只留最小必要部分 |
| 中间产物、一次性脚本、fixture、构建日志 | 任务临时根 | 收尾删除 |
| 私有配置、开发数据库数据 | 既有的持久位置 | 持久 |
| 报告的公网副本 | R2，见 [R2 分享对象](cleanup.md#r2-分享对象) | 交付的永久保留 |

- **报告和证据不进仓库**，除非用户本次要求或项目指令规定入库。仓库里不留 `.task-artifacts/`、`REPORT.*`、截图、`tsconfig.tsbuildinfo`。
- **工作区根只放仓库、`reports/` 和 `evidence/`。** 不在这里运行会生成 `node_modules`、缓存或构建输出的命令。
- **不另起任务目录。** `~/.cache/<任务>`、`~/.local/share/<任务>`、仓库内 `.worktrees/` 都不用。
- **用户或项目另有约定的照约定**，收尾时仍回收其中的一次性内容。
- **报告目录只放交付物。** 不放完整的运行现场、重复的 body 或 HAR 快照、私有配置和真实业务数据。

## 创建时为回收做准备

- **任务名。** 任务开始时定一个，只用字母、数字、点、下划线和连字符。临时根、worktree、容器标签和分享登记都用它，收尾扫描按它找回本任务的东西。交接里写明任务名、源码工作区、临时根和报告目录。
- **临时根。** `mktemp -d "${TMPDIR:-/tmp}/<任务名>.XXXXXX"`，所有 worker 共用这一个。测试、构建、脚本带 `TMPDIR=<临时根>` 运行，`mktemp`、Node、Bun、Python 的临时文件都会落在里面，随临时根一起回收。长驻服务不这样跑，临时根删除后它会找不到自己的文件。
- **Docker。**
  - 一次性容器用 `docker run --rm`。
  - 要留到任务后段的加 `--label owner=<任务名> --label purpose=<用途> --label release-when=<条件>`，条件是本任务结束前能核对的事件；删除用 `docker rm -v`。
  - postgres、redis、minio 每次启动都会生成匿名卷，要保留的数据用带标签的命名卷或绑定挂载。
  - `docker compose down -v` 只用于整个项目都属于本任务的情况。
  - 未加标签的容器和卷视为归属不明，不回收。
- **测试 teardown 覆盖失败路径。** 临时目录、容器、端口、数据库都要清理；项目测试漏清理的当 bug 修，或指出位置。
- **长驻进程**用 `systemd-run --user --scope`，unit 名带任务名，收尾按 unit 停止。
