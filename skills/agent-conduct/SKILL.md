# Agent 守则

三件事：会话一开始就命名；按用户的意图把事做完，说完成前核对并往前想一步；对自己在本机留下的东西负责。命名适用于所有会话，包括只读问答。

细则按要做的事读对应的一份：

| 要做的事 | 读 |
| --- | --- |
| 放报告和证据、起容器或长驻进程 | [资源落点与创建](references/resources.md) |
| 建隔离工作树、清理合入后的分支 | [Worktree 与分支](references/worktree-branch.md) |
| 收尾回收、保留资源、删 R2 分享对象 | [收尾](references/cleanup.md) |
| 向 `lobehub/lobehub` 提交、跟进或合并 PR | [社区 PR](references/community-pr.md) |
| 命名被跳过、给子 Agent 交接命名 | [会话命名细则](references/session-naming.md) |

## 会话命名

会话开始或主任务切换时，任务一明确就运行，先于其他技能和实质工作：

```bash
bun <skill-dir>/scripts/name-session.ts --type <FEA|DES|FIX|OPT|REL|EXP|DOC|RES> --topic '<主题>'
```

- 主题用用户的语言，简短具体，不重复项目名。其余由脚本完成，结果以输出为准；`named` 为 `false` 时保留原标题，在回复里说一句。
- 同一目标下的追问和子任务不重命名；主任务切换时，新标题合并前后任务的关键信息。
- 子 Agent 和 worker 不改父会话的标题，除非交接里明确交给它。

## 责任心

「完成」指用户要的结果在真实链路上做成并验证过，约定的交付物也都交了。说完成前对照目标逐项核对，没做到的直接说，并在本任务内补完。

- **按意图执行，不照抄字面。** 指令里的名字、数量或环境和上下文对不上时，先判断是不是笔误：能确定的按正确的做并说明改了哪里，确定不了的先问。写生产环境和难撤回的数据前必须核对。
- **往前想一步。** 交付前想用户接下来会问什么：授权范围内且可撤回的直接做掉；推送、合并、部署、生产写入不代做，把现状和所需信息写明。

| 刚做完 | 一并做掉或交代 |
| --- | --- |
| 改了代码 | 提交、推送、部署各到了哪一步 |
| 改了用户可见的行为 | 验收报告和分享链接 |
| 改了生产配置或数据 | 改前改后的值、回滚点、真实请求的验证结果 |
| 升级了依赖或 SDK | 相关服务一起启动后的全流程回归结果 |
| 开了 PR | CI 和评审状态，离合并还差什么 |

### 基线反例

- SDK 升级只跑了局部集成和单测就说完成，用户追问才补全流程回归。
- 浏览器验收做了，却只给一份自拟的 Markdown 记录，没交 HTML 验收报告。任务叫「修复」不是免除的理由。
- 用户把 `acme-google` 误写成 `ace-google`，上下文里全是 `acme`，仍照字面改了生产路由。

### 合并与发布反例

- 「全部合入主线并发布新产物」却只开了 PR，还要用户再授权。整条指令已经授权了合并和发版：按仓库门槛合入，核验后发布并验证产物。PR 已明确时，一句「合并」就足以授权。
- 「发下最新的 admin」却只检查了旧镜像。应核对发布分支的最新提交，跟进它的发布，以实际产物验收；CI 起不来先查项目已有的恢复路径，仍受阻就报告哪个提交卡在哪一步。

## 本机资源

- **任务名是归属标记。** 任务开始时定一个任务名（字母、数字、连字符），之后建的东西都带上它：临时根 `mktemp -d "${TMPDIR:-/tmp}/<任务名>.XXXXXX"`，worktree `wt.ts add --name <任务名>`，容器 `--label owner=<任务名>`，分享 `share.ts --task <任务名>`。测试、构建、脚本这类一次性命令带 `TMPDIR=<临时根>` 运行，它们的临时文件也落在里面。worker 沿用父 Agent 的任务名和临时根。
- **落点。** 报告放 `<工作区根>/reports/`，证据放 `<工作区根>/evidence/`，中间产物放临时根。报告和证据不进仓库，工作区根（仓库的上一级目录）不放别的。
- **容器和进程。** 一次性容器用 `docker run --rm`；要留的再加 `purpose`、`release-when` 标签，删除用 `docker rm -v`。长驻进程用 `systemd-run --user --scope`。
- **Worktree 和分支只走脚本。** 用 `wt.ts add`、`wt.ts remove` 和 `branch.ts`，不直接 `git worktree add`，不手动删分支。
- **手动清理只动本任务的。** 不用 `prune`、`docker compose down -v`、批量 `rm /tmp/*` 这类宽泛命令；归属不明的保留。

### 收尾回收

```bash
bun <skill-dir>/scripts/scan.ts --task <任务名> --workspace <工作区根> --clean
```

收尾前运行。脚本清掉本任务的临时根和其他低风险项，列出带任务名的容器、worktree、分享页面，以及任务期间新出现却没有标记的东西，按输出里的规则处理。父 Agent 一并回收 worker 留下的资源。

### R2 分享对象

交给用户的文档、报告和证据，分享链接永久保留。自测和核对失败的上传，收尾时用 feature-delivery 的 `share.ts remove --task <任务>` 删除。

## 社区 PR

向 `lobehub/lobehub` 提交、跟进或合并 PR 前读 [社区 PR](references/community-pr.md)。创建前经用户同意；能否合并只认 `community-pr.ts check`；用户已授权合并的，达到门槛后代为合并。
