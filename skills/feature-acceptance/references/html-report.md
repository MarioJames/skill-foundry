# HTML 验收报告

仅在既有流程需要或用户要求独立验收报告时读取并应用。默认人读产物为 `REPORT.html`，已有命名可保留 basename 并改用 `.html`；明确指定格式时遵从用户。普通问答或静态审查不额外制造报告，内部 Markdown 计划、进度记录不强制转换；机器契约依赖 Markdown 时可保留内部兼容产物，人读报告仍用 HTML。

## 可直接阅读的产物

报告采用 UTF-8 单文件静态 HTML，CSS 内联，直接通过 `file://` 打开即可阅读；不依赖外部 CDN、字体、构建步骤或服务，核心内容无需 JavaScript。必要附件可通过相对路径链接，报告正文不依赖附件才能看懂结论。

根据实际内容安排信息层次，顶部先展示实际结论、验证范围、被测版本和日期。清晰区分通过、失败和未验证，状态同时使用文字，不只靠颜色；未执行、证据缺失或被阻塞的项目不能填成通过。问题要说明影响、复现条件或步骤、修复结果及复验依据，未解决项保留其限制。

用目录锚点定位较长报告，用原生 `details` 折叠次要明细；实际结论、关键问题和未验证项保持直接可见。长表格、截图和路径在窄屏可读，打印时保留核心信息，并避免折叠明细成为必要信息的唯一入口。无需固定模板或为了填满版式补造内容。

## 证据与资源交接

保留既有 JSON 机器结果，HTML 引用必要截图及已存在、清理后仍保留的证据附件，不重复存储大体积证据，不在正文嵌入大量原始请求 body 或 HAR。核对链接指向交付位置，不链接即将清理的临时路径；发布报告前检查密钥、cookie、凭据及其他敏感内容，附件同样遵守原流程的脱敏要求。

说明服务、浏览器和验证进程的实际释放情况；说明数据保留或回收的范围及原因，保留运行资源时写明端口及归属。这里记录既有清理与保留政策的执行结果，不因生成报告改变资源释放条件或取得删除数据的授权。

交付前直接打开 HTML，核对结论与证据一致、必要链接可达，以及窄屏和打印的可读性。报告可读性检查不能代替对被测对象的实际验收。
