# Feature Acceptance

让 Agent 在实现前采用用户习惯，在交付前主动发现同类偏差，减少重复纠偏。本技能保存个人工程偏好和基础实现约束，不是某个业务系统的需求清单，也不要求每条偏好都适用于所有项目。

## 前端协作与读取

- 按用户或项目要求，在 UI 修改前读取 `lobe-design/SKILL.md`，再按其路由加载命中的参考；组件选择、`cssVar` token、视觉工艺和设计标准由它维护，本技能不复制组件目录或主题规则。不使用 Lobe 的项目保持既有技术栈。
- 页面、列表、表单、抽屉或异步流程实现前读取 [交互与状态](references/frontend.md#交互与状态)，涉及输入与草稿再读 [表单与输入](references/frontend.md#表单与输入)，涉及查询与展示再读 [详情与展示](references/frontend.md#详情与展示)。本技能检查状态、边界及恢复，项目已有 `ux` 时同时读取并沿用其交互规范，不另建一份产品行为定义。
- 设计问题按 `lobe-design` 的症状路由复核，交互问题按本技能对应参考复核；放行仍需下节的实际浏览器证据，扫描零命中不代表交互或设计合格。

## 使用

1. 先读本次需求与项目约定，再读 [工程选择原则](references/preferences.md)，从 [规则索引](references/review.md) 选择相关的前端、后端约束；采用 Lobe/Admin 范式的项目同时读取项目范式补充。开始实现时就使用这些约束，不等用户指出问题后才读取。
2. 确定变动范围，运行扫描；结合项目已有 lint、类型检查和相关测试完成确定性检查，扫描列出的项目命令只是候选，核实后按项目包管理方式执行。
3. Agent 重点检查脚本不能判断的组件选择、布局、封装、职责和行为，沿共享组件及调用点检查同类偏差；当前业务结果以本次需求为准，不从历史项目推定。
4. 有修复授权时处理并复验；出现可复用纠偏时，按 [反馈沉淀](references/evolution.md) 查重并在同次修复中更新所属技能或项目门禁，使下一次实现与验收能读到它。

本次明确要求优先于项目既有约定，项目既有约定优先于本技能的个人默认偏好；不因应用偏好切换技术栈或扩大业务范围。

```bash
# FA_DIR 为实际加载的技能目录，PROJECT 为项目根目录
bun "$FA_DIR/scripts/accept.ts" scan --project "$PROJECT"
# 只扫描指定 commit 到当前工作树的变动文件及未忽略的新文件
bun "$FA_DIR/scripts/accept.ts" scan --project "$PROJECT" --base "$BASE_COMMIT"
```

需要 Bun ≥ 1.3、ripgrep，Git 项目另需 Git。脚本不执行项目代码，返回 `0` 仍需审查，`1` 表示已激活规则命中门禁，`2` 表示错误或覆盖不完整；有缺失工具时如实报告自动检查未完成，继续可执行的审查。扫描范围、CLI 和项目规则格式见 [脚本契约](references/rules.md)。

## 实际验收

- 后端沿用项目测试和授权环境，核对实际接口、失败反馈及数据变化；不因验收自行迁移、seed 或 reset。
- 前端完成真实浏览器交互及 console/network 检查；使用 browser-harness 时向它交接功能范围、被测版本、关键路径和预期，已有服务同时交接实际 APP_URL、所有者及保留要求，其环境、登录态、采证与清理由该技能负责。
- 独立使用时采用项目已有浏览器工具完成同样的交互验证；项目指定 browser-harness 时遵循该入口，不因本技能支持独立使用而绕过。

只审查源码不能宣称运行验收通过。报告具体问题及文件位置、相关规则、实际证据和未验证项，不逐条复述整个规则库；前端同时给出 APP_URL、关键页面结果、console/network 错误及资源释放情况。复验对应当前版本，只清理自有进程并保留项目数据。

用户只要求审查时不改实现和规则；已要求沉淀项目规范时完成规则写入与下次读取入口，不只返回建议。技能自身验证按需使用 asset-validation。
