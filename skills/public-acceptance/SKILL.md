# 公网验收

最小流程：启动或复用项目 → 创建隧道 → 整理交付信息。服务和隧道各准备一次，已有准备结果直接沿用。

用户要求公网验收或暴露到公网即授权本流程；只要求本地验收不建隧道，只查询状态或清理则直接走 [隧道生命周期](references/tunnel-lifecycle.md)。使用本地 DEV 环境和项目现有脚本，不改公共 `.env`、不自动安装系统工具，不把生产或敏感数据暴露到匿名隧道。

## 1. 启动或复用项目

- 已有本轮确认的 `APP_URL`、进程和日志时直接复用。没有准备记录时，按 [DEV 服务](references/dev-service.md) 一次查明目标项目的服务；已有服务复用，没有运行或启动中的服务才启动开发脚本。
- 以启动日志和实际监听端口确定 `APP_URL`，不照抄默认端口。归属或端口有歧义时才补查进程、响应；正常路径不额外做本地 HTTP 探活，也不重复全量扫描。服务退出、启动超时或无法确认归属时报告阻塞。
- Herdr 可用时，新服务在独立 tab 的 pane 前台运行并落盘日志；已有服务复用原 pane 或日志，不为展示另建日志 pane。Herdr 不可用时使用宿主已有的持久进程方式，记录 PID、日志和停止方法。操作细节见 DEV 服务参考。
- 前后端分离时沿用开发代理，公网页面的 API 不应指向验收者机器上的 `localhost`。必要的 Host、origin 或回调差异按项目实际支持的方式配置。

## 2. 创建隧道

- 以已确认的本地 origin 执行一次 `cqt start`，全程使用任务专属绝对 `--state-dir`，见 [隧道命令](references/tunnel-lifecycle.md)。已有本轮隧道直接复用；仅对已由 `browser-harness` 项目 target 管理的服务使用其 `share`，不再另建隧道。
- 从成功命令的结构化输出取得 `PUBLIC_URL`、PID 和日志。以真实入口的 path/query/hash 生成验收地址；已有 `REMOTE_REVIEW_URL` 时直接使用。
- 生成地址后立即交付。`start` 只等待地址生成，不等待 HTTP/TLS 探活；隧道后台托管，不另建 pane。

## 3. 确认页面并整理信息

- 有登录时，从实际生效的开发配置、登录实现或 seed 定向查找用户名、可取得的明文密码、角色和来源。需要查库时沿用项目工具，只读查询当前 DEV 数据库的必要账号字段。示例配置不是当前凭据，数据库连接密码不是应用密码。
- 凭据只交付当前用户，不写入仓库、日志、URL 或公开证据。只有密码哈希时说明无法还原；SSO、验证码等说明登录方式；无登录则写“无需登录”。不猜密码、不擅自建号或重置。
- 使用 `browser-harness` 打开一次最终公网地址，确认显示目标项目页面（登录页也算），记录打开结果及明显加载错误。本技能只检查页面可达性，不提交登录、不遍历关键页面、不测试业务流程；账号信息标明“未验证登录”。自行准备的服务使用 URL target，避免项目目录 prepare/publish 重启服务；已由 harness 管理的保留原 target。没有该技能时如实标记页面可达性未验证。
- 浏览器结果就是本轮可达性证据，不再叠加 curl、定时轮询或固定 60 秒复查。首次失败记录实际错误并保留同一地址，不因暂时的 DNS/TLS/5xx 重建隧道；只有修复了具体问题或用户要求复查时才再验证。拿到 URL 不代表页面已可达，页面打开也不代表登录或业务功能通过。属于当前已授权开发范围的具体问题继续修复，超出范围则交付阻塞原因。

最终交付：`APP_URL`、公网验收地址、账号/密码或缺失原因、页面打开结果（账号未验证登录），以及资源记录（PID/端口、日志、pane/tab、状态目录或 target、归属和清理命令）。已先行给出地址，最终仍保留完整入口信息。

## 保留与清理

给用户手动验收时保留 DEV 服务和隧道，关闭本次浏览器及验证进程。用户结束验收后，隧道用原 state-dir cleanup；harness 管理的资源用原 target cleanup。随后按 [DEV 清理](references/dev-service.md#保留与清理) 释放本任务新建的服务和 pane，复用资源及项目数据保留。

启动或建隧道失败且没有可交付入口时，清理本任务新建的资源并保留诊断日志。清理前核对精确进程身份，清理后确认退出，不宽泛杀进程。
