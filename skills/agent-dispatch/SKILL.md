# Agent Dispatch

仅父任务所有者运行调度循环。受委派工作者完成自己的交付，不递归派发、不改父 tab 名称。技能处理宿主已经投递的消息，不能拦截宿主队列或保证自动唤醒。

## 收到新工作时

首次接到包含多个交付项的任务，以及每次收到已投递的新增/变更指令、拆出独立工作、收到子任务完成/失败/阻塞结果时，先执行本节，再继续编辑、长步骤或阻塞等待。加载技能和决定派发是两步；不能等自己已经决定并行才加载技能。

1. **盘点工作。** 合并新指令、当前正在推进的工作、尚未推进的待办和积压问题。记录每项的状态、现有所有者、目标产物、依赖、读写范围及缺失事实，不先判定哪些“值得并行”。纯状态询问且工作集合未变时直接回答。
2. **把盘点结果交给 Jev。** 当前工作作为并行背景，未推进工作作为待判断项；即使新增指令只是修正，也重新看积压工作是否能推进。由 Jev 判断语义独立性、并行收益和组合，不让父任务先以“同项目”“同页面”“任务小”或“自己做更快”筛掉待办。单项入口把当前工作和积压问题写入 `goal/constraints`，具体交接放入 `prompt`；多个待判断项使用 [批次入口](references/jev-scheduling.md) 的 `tasks`，不要只发送父任务已经选中的一项。
3. **按结果启动。** Jev 选择可独立执行的工作且达到采纳门槛后，按有效引擎与交互需求使用 JSON-RPC 后台任务或 Herdr pane（见下表），及时派发；父任务继续自己的无冲突工作。serial、缺上下文、未达门槛或调用失败均如实处理，不反复请求凑过线。
4. **结果回来再盘点。** 收取、验收产物，更新待办与依赖后重新执行本流程。用一句进度说明交代实际处置，沿用任务状态，不另建触发台账。

父任务提供事实并执行权限、依赖、资源归属、容量和能力等硬检查；硬阻塞项保留在盘点中并标明原因，不伪造可派发状态。现有入口在硬检查后没有可执行组合时不会请求 Jev，应明确说明“本地阻塞，未调用”；只有当前一个不可再拆的操作且无积压工作时直接处理，不为调用凑任务。加载技能、请求 Jev、实际派发是三个不同状态。

- 替换或取消只终止被替换的工作；先确认执行已停、核对部分产物，再移交其写入权。保留其他未被替换的目标。
- 读正在变化的文件、Git index、锁文件、数据库、服务也算资源冲突。先划清范围或等待必要产物冻结；需要隔离时用 `cow-workspace`，文件隔离不隔离外部数据。
- 说明时区分：只有一个原子操作且无积压，或全部组合被硬检查阻止（未请求 Jev，附具体原因）、Jev 选择 serial、Jev 选择并行但置信度未达门槛、调用失败、已派发。未调用不能归因为“概率不够”；技能已读也不能声称已经执行 Jev 判断。

## Jev 与执行配置

唯一配置是 `~/.config/herdr/agents.json` 或显式 `--config`；保留这个历史路径以继续采用已有个人覆写，不复制出第二份默认配置。先解析 `manual_override`，否则按难度取 `routes`，再决定执行载体。

- **存在 override：跳过 Jev 的难度分类/模型路由，只让 Jev 判断是否并行、如何组合执行。** 记录为 configured，不虚构难度，不改变已选模型与力度。
- 无 override：难度判断确有歧义时调用 Jev A；有充分依据的父 Agent 分类可直接记录。Jev B 从通过本地检查的候选组合中选择，也可返回 serial/need_context/owner_required。serial 是正常的“收益不足，父任务处理”，不是缺权限或失败。
- Jev 判断并行方案，普通交接不可用父 Agent 的独立性说明跳过 B。有 override 时，批次 `owner_wave` 也不跳过 B。无 override 的复杂批次只在用户已明确指定执行组合时可采用原 owner_wave；不要把“可以独立交付”等同于用户已决定调度。
- 缺权限、必要输入、归属或能力证据时由父任务处理，不让 Jev 猜。Jev 不改本地硬门槛、不接受产物、不证明模型可用。请求失败、低置信度或缺 key 显式回父任务，不重试或换模型。
- 普通单项 Codex oneshot 的 B 采纳门槛为 0.65；难度 A、持久/非 Codex 路径和完整批次保留 0.80。门槛来自有限场景校准，不是正确率保证；不能拿它代替授权、依赖和资源检查。低置信度退出需区分 Jev 原始选择与本地采纳结果，不能说成 Jev 判定不可并行。

只有一个待判断项时，使用 [run-task 用法](references/run-task.md)，脚本复用已有模型配置、准入和状态实现，父 Agent 不维护 RPC 循环。有多个未推进工作需要判断时读取 [Jev 批次流程](references/jev-scheduling.md)，可复用原 A/B 流程；不要为普通交接手写完整批次。

## 选择执行路径

| 任务 | 路径 |
| --- | --- |
| 有界一次性交付，有效引擎为 Codex | 独占 `codex app-server` 的 JSON-RPC runner，交付后自动终止自有执行资源 |
| 要持续多轮交互、保留终端或运行服务 | `herdr` 技能的持久 tab/pane，按原生 profile 启动，按需要复用 |
| 有效引擎为非 Codex（包括 Qoder override） | 现有 Herdr adapter；不可用时回父任务，不暗改成 Codex |

按交互和资源需求判断长程，不用耗时阈值切换路径。一次性终端命令的 Herdr `oneshot` lane 与后台 LLM 任务是不同入口。

## 后台交付与收尾

通过宿主的后台执行能力启动 runner，取得句柄后继续原任务的无冲突工作；不要启动后立即阻塞等待。收到追加任务时先 reconsider；没有独立工作时再有界等待并收取结果。宿主无完成通知时在自然检查点查已知句柄，不另造 watcher/daemon。

同一父任务 scope 只用一个 `--state`；RPC 与 Herdr attempts 共用容量与写入预留。普通交接显式提供父任务和相关外部活动的身份、adapter、读写范围；批次流程还读取 Herdr inventory。声明不是 OS 隔离，也不提供跨独立调度器的全局事务。unknown 持续占用，不能另开状态文件绕过。

runner 自行处理协议、审批退出、超时、取消、终态和进程回收。它只允许 read-only/workspace-write 与 never 审批；需要新增审批或交互时返回 needs_owner，不自动批准。父任务把权限限制和验收标准写进交接；子进程配置继承不代表新的授权。

执行完成与验收分开：观察精确 attempt 的结果与 cleanup，再验证产物，accept 后才能解锁依赖和移交写入权。失败/取消/未知结果需检查部分写入并显式 resolve；重复消息不重放同一 revision。不能以进程退出、Agent 空闲或自报成功代替验收。

只释放本任务自有进程/终端，保留产物、诊断与持久数据。最终说明已验收交付、验证证据、执行资源释放情况和保留原因。
