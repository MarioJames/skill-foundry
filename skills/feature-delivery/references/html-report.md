# HTML 验收报告

用户可见的行为有变化、既有流程需要或用户要求验收报告时读取并应用，适用范围以 SKILL.md 的「验收」一节为准。默认人读产物为 `REPORT.html`，已有命名可保留 basename 并改用 `.html`；明确指定格式时遵从用户。普通问答或静态审查不额外制造报告，内部 Markdown 计划、进度记录不强制转换；机器契约依赖 Markdown 时可保留内部兼容产物，人读报告仍用 HTML。

## 用脚本渲染

报告由 `report.ts` 从检查结果 JSON 渲染，不手写 HTML。JSON 放在任务临时根，人读的只有 HTML：

```bash
# FD_DIR 为 feature-delivery 技能目录
bun "$FD_DIR/scripts/report.ts" render --input "$TMP_ROOT/result.json" --out "<工作区根>/reports/<主题>-<日期>/REPORT.html"
```

```json
{
  "title": "订单列表筛选验收",
  "scope": "订单中心",
  "summary": "一句话实际结论，含关键问题",
  "meta": { "被测版本": "abc1234（含未提交改动）", "日期": "2026-11-05", "APP_URL": "http://localhost:3010" },
  "checklist": "../1105-订单列表筛选.html",
  "checks": [
    {
      "id": "A1",
      "title": "无结果时显示空态",
      "status": "pass",
      "expected": "筛选无结果时显示空态和清除筛选入口",
      "observation": "空态与「清除筛选」可见，点击后恢复全部 24 条",
      "evidence": [{ "path": "../../evidence/orders-1105/empty.png", "description": "筛选「已退款」无结果时的空态，右上角为清除入口" }]
    }
  ],
  "sections": [{ "title": "资源", "items": ["dev server（unit dev-orders-filter）已停止", "开发库未改动"] }]
}
```

- `status` 只用 `pass` / `fail` / `blocked` / `skipped`。顶部总结论由脚本按检查项推出：有失败为「不通过」，有阻塞或未执行为「未完成」，全部通过才是「通过」，不手填。
- `scope` 可省略，写所属产品或模块，显示在标题上方，与设计文档顶部的写法一致。
- 检查项按设计环节的验收清单逐项列出：`id` 与清单编号一致，`expected` 照抄清单的预期，顺序跟清单走；清单外发现的问题追加在后面，编号 `X1`、`X2`…。
- 有设计文档时 `checklist` 填它相对 HTML 文件的路径，脚本读出其中的 `data-check-id`，有清单项没有对应检查项或缺 `expected` 就报错并不写出报告；验收清单只在回复里列出时省略此字段，按回复里的编号自行核对。清单里有场景分组行（`<tr class="group">`）时，报告按同样的场景分组并沿用其编号和标题，清单外的检查项归入「清单外发现」，清单里标了「异常场景」的项在报告里同样标出；分组、标题和标记都不在 JSON 里重复填写。
- 每项写实际观察；未执行、证据缺失或被阻塞的写原因，不能填成通过。
- 证据 `path` 相对 HTML 文件，指向 `<工作区根>/evidence/` 中清理后仍保留的文件；`description` 写图里能看到什么、证明了哪条预期。脚本对缺文件、缺描述、绝对路径直接报错并不写出报告。
- `sections` 放未验证项说明、资源释放和数据保留等收尾信息，不放调研过程。
- 只引用你用图片查看工具实际看过的截图。

## 阅读体验

- 视觉语言与设计文档是同一套：纸面网格底、墨色细线框、衬线标题、等宽注记，只有浅色。色板和字体在 `report.ts` 与 [设计文档模板](../assets/design-template.html) 各有一份，改动时两处一起改，测试会核对两份取值一致。
- 首屏是结论章（通过 / 不通过 / 未完成，带通过项数）、一句话结论、被测版本等元信息；有未通过项时再列各状态数量和「需关注」清单，逐项链接到对应检查项，全部通过时不出现。
- 检查项按场景分组，每组标题右侧是本组结果；每项左侧为编号和状态，右侧标题下左右对照「预期」与「实际」，证据缩略图带编号说明排在「实际」下方。失败、阻塞、未执行的行整行着色，通过的行不着色。
- 图片缩略图点开后，图和它的描述一起放大：桌面左侧图片区占 60vw，图片按宽度撑满、超出高度在图片区内上下滚动，右侧为描述；←/→ 在同一检查项的证据间切换，点图在适应窗口和原始尺寸间切换，Esc 关闭。
- 单文件、CSS/JS 内联，`file://` 直接打开，不依赖 CDN、字体或服务。JS 只做放大查看的增强：不开 JS 时缩略图就是原图链接，描述常显，打印时保留缩略图和描述。
- 长路径、SHA 与 URL 必须可换行，包括附加说明列表；在桌面宽度下用实际长文本验证 `document.documentElement.scrollWidth <= innerWidth`，避免正文通过而资源或提交列表撑宽页面。

## 证据与资源交接

保留既有 JSON 机器结果，不重复存储大体积证据，不在报告里放大量原始请求 body 或 HAR。核对链接指向交付位置，不链接即将清理的临时路径；发布报告前检查密钥、cookie、凭据及其他敏感内容，附件同样遵守原流程的脱敏要求。

在 `sections` 中说明服务、浏览器和验证进程的实际释放情况，以及数据保留或回收的范围和原因；保留运行资源时写明端口及归属。这里记录既有清理与保留政策的执行结果，不因生成报告改变资源释放条件，也不因此取得删除数据的授权。

交付前在浏览器打开报告，核对结论与证据一致、图片能放大且描述完整。报告只做桌面版式，不加手机端或窄屏样式，也不做窄屏检查。报告可读性检查不能代替对被测对象的实际验收。

交付时按 [分享链接](../SKILL.md#分享链接) 上传，报告引用的证据和设计文档随页面一起发布，回复里给公网链接。
