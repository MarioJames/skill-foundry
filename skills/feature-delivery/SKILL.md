# Feature Delivery

一个功能分三段：设计时只让用户拍板必须由他决定的事，实现时直接采用用户习惯，交付前主动发现同类偏差。本技能保存个人工程偏好和基础实现约束，不是某个业务系统的需求清单。本次明确要求优先于项目既有约定，项目既有约定优先于本技能的默认偏好；不因偏好切换技术栈或扩大业务范围。

## 设计

- 有待用户拍板的点才出 HTML 设计文档：用真实数据按场景对照现状和改后，前端加页面全景。用户已给全套方案或没有待拍板点时，写下已定方案和清单后直接实现。纯修复、配置和文档类小改动不出设计文档。
- 设计环节同时定下验收清单：每项有编号、操作、可判定的预期和验证方式，覆盖改后场景、本次会遇到的失败与恢复路径、可能波及的不变行为。没有设计文档时，开始实现前在回复里列出。
- 已完成的功能要对外展示又不能暴露真实页面时，出方案展示页。

## 实现

1. 读本次需求、已拍板的设计和项目约定，再按上表选相关约束。开始实现时就用上，不等用户指出问题才读。
2. UI 设计与修改先按 `lobe-design` 选阶段和参考；组件、token 和视觉标准由它维护，非 Lobe 项目沿用既有技术栈。项目有 `ux` 规范时沿用，不另建一份产品行为定义。
3. 运行扫描，并跑项目已有的 lint、类型检查和相关测试。扫描列出的项目命令只是候选，核实后按项目的包管理方式执行。
4. 自己检查脚本判断不了的部分：组件选择、布局、封装、职责和行为，沿共享组件和调用点找同类偏差。业务结果以本次需求为准，不从历史项目推定。
5. 有修复授权时处理并复验。出现可复用的纠偏时，在同次修复里更新所属技能或项目门禁。

```bash
bun <skill-dir>/scripts/accept.ts scan --project <项目根> [--base <commit>]
```

退出码 `0` 仍需审查，`1` 表示已激活的规则命中门禁，`2` 表示出错或覆盖不完整。缺工具时如实报告自动检查未完成，继续能做的审查。

## 验收

- 按验收清单逐项执行：先读清单的最新版本，每项给出通过、失败、阻塞或未执行，附实际观察和证据，编号与清单一致。不合并、不跳过、不改写预期。清单外发现的问题追加为 `X1`、`X2`…。修复后复验失败项和共用代码路径的项。
- 前端按 `browser-harness` 做真实浏览器交互和 console、network 检查，向它交接功能范围、被测版本、验收条目和预期；已有服务再交接实际 APP_URL、所有者和保留要求。项目指定了入口就用它。
- 后端沿用项目测试和授权环境，核对实际接口、失败反馈和数据变化；不因验收自行迁移、seed 或 reset。
- 只审查源码不能说运行验收通过；扫描零命中不代表交互或设计合格。
- 用户只要求审查时不改实现和规则；要求沉淀项目规范时，把规则和下次读取的入口都写好，不只给建议。

## 交付物

- **验收报告。** 用户可见的行为有变化，就交付 HTML 验收报告和分享链接：新功能、行为变更，以及改了用户可见行为的修复都算。判断看行为，不看任务的叫法和改动大小；做过浏览器验收或多场景验收的任务一律出报告。Markdown 验收记录和回复里的文字结论不能代替它。
- **例外。** 只有不改变用户可见行为的改动（重构、配置、文档、内部实现的修复）可以不出报告，此时在回复里写明依据并给出实际验收结果。用户另有要求时照做。
- **设计文档。** 新功能和有待拍板点的行为变更另交付 HTML 设计文档。
- **生成和上传。** 报告用 `report.ts` 从结果渲染，默认名 `REPORT.html`，有设计文档时由脚本核对清单覆盖；然后按「分享链接」上传。最终回复里要有公网链接和本地路径，缺了不算交付。
- **回复。** 报告具体问题和文件位置、相关规则、实际证据和未验证项；前端另给 APP_URL、关键页面结果、console 和 network 错误、资源释放情况。一次性验收资源按 [agent-conduct](../agent-conduct/SKILL.md#收尾回收) 收尾。

## 分享链接

```bash
bun <skill-dir>/scripts/share.ts upload --file <工作区根>/reports/<文件>.html --task <任务名> [--name <名称>] [--mission <主任务>] [--public]
```

设计文档和验收报告只做桌面版式，交付时上传，回复里同时给公网链接和本地路径。默认私有，给外部看的展示页才加 `--public`。文档修订后用新名称上传，旧版本保留。交付的链接永久保留，自测和核对失败的上传按 [agent-conduct](../agent-conduct/SKILL.md#r2-分享对象) 删除。上传规则、邮箱地址的写法和配置见 [分享链接细则](references/share.md)。
